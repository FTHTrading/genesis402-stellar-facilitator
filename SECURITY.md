# Security

Report issues to kevan@unykorn.org. Please do not open public issues for exploitable findings; we will acknowledge within 3 business days.

Scope of this document: the code in this repository as run on Stellar **testnet**. There is no mainnet deployment and no hosted instance (**NOT DEPLOYED**). Mainnet is a separate milestone with its own review.

## Trust model

- The facilitator holds one Stellar keypair that pays transaction fees. It never holds buyer funds: a valid payload moves tokens `buyer → seller` inside the token contract, authorized by the buyer's own signature, and the facilitator is rejected as `from`, `to`, transaction source, operation source, or authorizer.
- The buyer trusts nothing but the token contract and their own signature: the authorization entry binds the exact invocation, network, nonce and expiry.
- The seller trusts the facilitator's `/verify` and `/settle` answers and should run its own facilitator or one it controls. The facilitator URL is configuration, never taken from a request.
- The discovery index treats every manifest and every seller response as attacker-controlled input.

## Known limits (T1, after review round r1)

- Settlements are serialized per signer (one per ledger). Channel accounts for throughput are T2.
- Replay is a refusal, by design: a signed entry whose nonce this facilitator already consumed is never settled again, even if the recorded transaction later proves to have failed. A reconciler that checks recorded hashes on chain and frees rows for transactions that never landed is not built (the reviewer's crash test documents the liveness cost; the safety direction holds).
- The 409 `settlement_pending` state (payment digest → claim key, hash) is written to the configured `pendingStore` **before** `/settle`. With the default in-memory store a seller restart forgets it, and the buyer's retry then goes through `/verify` → `nonce_reused` → 402; the SDK deliberately does not deliver on `nonce_reused` (that path was the r2 Critical). Pass `SqlitePendingStore` (or any shared store) to survive restarts and to share state across instances; this is the r3 ruling on M-r2-1.
- The SQLite pending store's lease lock (30 s) means a seller process that dies mid-request leaves the payment locked for up to 30 s before another process can resume it.
- The facilitator's fee account is a single hot key on testnet. Mainnet needs a funded fee account with a balance alert, a fee-bump signer separated from the sequence account, and a key-rotation runbook; none of that exists yet.
- The nonce store is SQLite on one host. Two facilitator instances sharing one signer would need a shared store or distinct signers.
- DNS rebinding is closed for the default fetch (connections pinned to the vetted addresses). An injected `fetch` (tests, custom clients) bypasses the pin and must do its own.
- `allowLocalTargets` / `DISCOVERY_ALLOW_LOCAL=1` exists so the demo can crawl `127.0.0.1`. A public index must never enable it.
- Rate limiting is per process. Without `TRUST_PROXY=1` the socket address is the identity; a deployment behind a proxy must set `TRUST_PROXY=1` and have the proxy overwrite `X-Forwarded-For`. Clients that cannot be identified at all (no socket, as in embedded use) share one coarse bucket.
- Ambiguous settlement (observed once on 2026-10-23 against the public SDF testnet RPC): when the answer to a submission is lost, the facilitator reports `unexpected_settle_error` / `settle_exact_stellar_transaction_not_confirmed` with the hash and keeps the claim. Since r1/r2 the seller SDK answers `409 settlement_pending`, keeps a pending record (payment digest → its own claim key, hash), and on the buyer's retry re-asks the facilitator with that same claim key (`Idempotency-Key`); the facilitator returns the recorded outcome only to the claimant that made the claim. A pending record expires after the envelope time bounds and auth expiry (2 × `maxTimeoutSeconds` + 30 s) and then yields a terminal 402. What remains: pending records live in the seller process; after a seller restart the retry reaches `/verify` → `nonce_reused` → 402 for a buyer who paid (safety over liveness; see M-r2-1 in the T1 report).
- The public SDF testnet RPC (`soroban-testnet.stellar.org`) is shared infrastructure and was intermittently unavailable during T1. Run against a dedicated RPC provider for anything beyond a demo.
- The facilitator API is open unless `SELLER_TOKENS` is set. Open mode is for self-hosting on the seller's own network; a hosted instance must set tokens. Even then, the fee-drain guard bounds what one hour of valid traffic can cost (`FEE_BUDGET_STROOPS_PER_HOUR`, `MAX_SETTLES_PER_SELLER_PER_HOUR`); both counters are per process and reset on restart.
- The settlement deadline (12 s) can report a settlement as ambiguous while the stalled call later completes; the claim is kept, so nothing is paid twice, but the seller sees `409 settlement_pending` until its retry re-reads the outcome with its claim key.

## Out of scope

Compromise of the buyer's signing key, of the token contract, or of the Stellar network itself.
